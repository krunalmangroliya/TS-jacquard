# Local product status

The local trial app is implemented: React editor, PNG sketch import and trace review, direct BMP/PNG/JPG/JPEG color image import, palettes of up to 256 colors, manual source-stroke hide/restore, node/handle/path tools, object editing, independent size variants, pixel corrections, indexed exports, searchable library, filesystem autosave, browser recovery, retained versions and explicit rebase review.

The owner explicitly selected use on this Windows PC. The loopback app and local filesystem storage replace the original studio server, Postgres and login deployment for this edition. Original production acceptance targets have not been declared passed. See [ADR 004](adr/004-local-product.md).

- Data: `data/jdm/`; original sample PNGs remain unchanged.
- Supplied sample: **Sample 1 · floral panel**, with six placeholder test colors. A separate trial copy and 1200-hook size were used to check editing/export without changing that master.

- Black-and-white strokes start visible with a measured width per edge. Gold uses filled contours with no extra outline, retaining solid ink and fine dark engraving. Hiding a stroke retains its geometry, fills and width. A palette merge changes colors; boundary deletion changes region topology.

## Direct color image workflow

- **Upload color image** in the library opens **Direct color image**; the import screen also lets the user switch to the existing **Sketch / line art** workflow.
- BMP, PNG, JPG and JPEG files are checked by their contents and browser decoding. Accepted sources have 8–8,192 pixels on each side, at most 40 million pixels, and at most 110 MB of file data. Cropping uses whole source pixels and a minimum 8 × 8 crop.
- **Keep original colors** is the default and preserves up to 256 decoded RGB colors exactly. **Reduce colors** is an explicit choice with a 1–256 limit and preview before saving. Inputs with more than 256 colors require that choice; preservation never silently reduces them. Transparent areas become white. JPEG shading can introduce additional colors that require reduction. The existing six-color starting palette for sketches is unchanged. See [ADR 006](adr/006-optional-color-reduction.md).
- **Prepare color image** → review the palette and source comparison → **Create image master** → choose output width and height → **Create size variant** → cleanup and **Pixel pencil** → indexed BMP export. Image resizing uses nearest-source-pixel sampling. Palette editing and merging remain available; vector node/fill tools are reserved for sketch masters.
- **Image interpretation** distinguishes square-pixel artwork from a prepared loom grid. A prepared grid with confirmed source read/EPI and pick/PPI uses source EPI/PPI once in the linked-size calculation. Unknown density keeps explicit pixel dimensions and disables linked proportions/Fit across; source density can be supplied by reimporting. BMP/PNG density is an optional suggestion requiring selection; invalid metadata and filename text do not determine sizing. Source interpretation is versioned; existing masters/sizes are not reinterpreted.
- Original PNG source bytes are kept. BMP/JPEG sources are decoded at full resolution, placed over white where transparent, and stored with lossless PNG encoding; their original file bytes and complete metadata are not retained. The saved master JSON includes indexed image pixels, palette, interpretation and confirmed source density. Cleanup and manual pixel corrections belong to each size, leaving the image master reusable. Source-master physical preview uses the source pixel aspect; size preview uses the target machine density.

## Color usage review

- Used colors occupying **0.1% or less** are shown with exact counts, percentages and swatches. Master counts cover every pixel of its full-resolution imported raster/crop; size counts cover final output pixels after cleanup and manual overrides, rather than a reduced preview. Unused entries are listed separately.
- A close, more common export shade may be suggested. **Review merge** opens the existing manual merge controls; it does not merge immediately. The designer can retain accents or choose a different target. Ground remains reserved. Pending renders do not present stale counts as current.

## Selective raster cleanup

- New image masters start with automatic cleanup off. Existing saved rules are preserved.
- **Preview gentle cleanup** proposes `minRegionPx: 2`, with thin-detail, checkerboard and outline processing off, while retaining scope, protected colors and manual pixels. A side-by-side current/proposed review offers whole-image and matching detail crops, changed-pixel highlighting, color-area deltas and processing notes. **Apply proposed cleanup** is one undoable action; **Keep current** makes no change. A preview cannot be applied after the underlying design changes.
- **Repair multiple line colors** previews 1–8 selected inks together against frozen source evidence; conflicting or nearby cross-ink edits are skipped symmetrically. Existing sampling, speck settings and restrictions are retained. Repair selections are remapped through palette merges/Undo and safe rebase, and included in saved/exported rules.
- **Show source detail** adds an aligned imported-source pane with exact crop coordinates; **Go to output pixel** also reaches unchanged marks. Source crops are decoded in the review worker with a bounded four-crop cache and stale-response guards. The review palette includes prior user merges. Small-region previews now accept an inclusive 1–64-pixel limit with 1 as default; applying replaces current cleanup settings. A changed scope can restore pixels previously cleaned outside it.
- New outline selections use `outlineAlgorithm: 'conservative'`: preservation and repair proposals use the same unchanged sampled baseline, and source connections plus competing-color details are checked before applying a batch. Small unsupported fragments and stroke expansion are rejected. Existing saved rules with no algorithm field retain legacy behavior; the user can **Preview conservative outline update** before adopting it. No stored design is automatically upgraded.
- Outline processing still requires downsampling, uses bounded source evidence, and does not infer connections across image edges. Difficult gaps and dots may be left unchanged. Explicit speck/thickness rules still need review because they can remove intentional detail. These operations retain indexed colors; their changed-pixel counts are not counts of proven defects.
- Cleanup can target chosen colors and a rectangle selected on the canvas or adjusted with pixel coordinates. Other areas/colors, protected colors and explicit overrides remain protected. The saved normalized area follows resizing; palette merges remap cleanup and outline color selections, with undo/redo.
- SAM was evaluated as a possible future object-selection assistant. No model or inference service is installed, and semantic decoration/noise detection is not claimed. Multi-color optimization, repeat normalization and learned defect decisions remain conditional future work. See the [implemented slice and remaining plan](plans/raster-cleanup-v2.md); [ADR 007](adr/007-source-aware-raster-cleanup.md) describes the earlier outline method.

## Remaining validation and improvements

- The implemented cleanup work is a first slice. Matched manual-reference region labels, independent held-out designs, timed NedGraphics touch-up, ambiguous dot/gap classification, multi-color optimization and optional model trials remain pending; see [the cleanup plan](plans/raster-cleanup-v2.md).
- Enter actual machine hooks/EPI/PPI and yarn palette values, then validate BMPs in the designer's NedGraphics installation.
- Measure cleanup time/pixels against Photoshop with a representative set of real designs. The original 80% reduction target is not yet measured.
- Dense panels still need several seconds for opening or exact rerenders. During dragging, the canvas deforms local curves and adjacent fills over a cached viewport; this visual preview is temporary and exports use the exact result. Large object transforms/duplication still process after release to preserve moved fill references.
- Temporary drag previews can show different crossing-stroke order, and exceptionally wide strokes at extreme zoom can leave outer fragments until the exact raster replaces the preview. These do not affect saved geometry or exported pixels.
- Very small strokes and minor details can fall below the output grid. Source-width variation within a single edge is approximated. Tracing and gap repair still need review.
- Straight repeat and panel modes are supported. Half-drop/brick seam editing is pending.
- Rebase replays by IDs and face references and reports skipped operations. Nearest-node recovery and conflict-location editing need improvement. Adoption checks whether the draft changed after the preview was created.
- Undo is bounded to 100 edits / 64 MB and lasts for the editor session. Versions are retained on disk. A forced browser/process kill during unfinished undo/redo can recover the last completed state; normal edits are written as pending before dispatch. A crash that skips lock release may leave a read-only lock until its five-minute expiry.
- Accounts, remote studio access, weave assignment and loom punching are outside this local edition.

The earlier CLI reports, generated reference image, source-stroke inspector and sessions remain available under `output/`, `eval/references/` and `docs/sessions/`. The original specification file has not been rewritten.
